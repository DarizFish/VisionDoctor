## 为什么追加这一轮

第四轮交付审查在真实修复案件中复现了来源错误：EV-067 属于修复后运行
`run-20260912T090708Z-293764aa`，但按相同路径 `parts/A/algorithm/output.json` 读取时，
旧 Toolbox 返回了原故障运行的数据（Z=0.253660810 m），与 EV-067 的已登记哈希不符。
正确修复后值为 0.183660810 m。

`run_recheck` 直接读取新旧 ObservationBundle，因此第三轮到位回证仍有效。
缺陷影响的是之后通过工具追问同一案件内的多次观察，不能因先前全量测试通过就忽略。

## 修正与验证

- 根据证据的 bundle_id 选择 FileBundleAdapter，核验已登记哈希；缺少来源时明确拒绝，不回退到另一运行。
- 图片交给视觉组件时使用该运行的实际文件，结果记录也按 run ID 和 part ID 读取。
- CaseService 向调查过程传入全部观察目录，保存后重载仍可正确读取。
- 模型目录、工具返回与工作台展示运行 ID，避免把同名路径当成同一条证据。
- 派生测量按其实际来源归属观察；跨运行测量标记为案件级，保留每个输入证据 ID。
- 工作台回证文案改为“本次任务结果通过复核”，不把本次到位结果外推为工位所有能力恢复。

主 RGB-D 相机和项目配方未改变；侧面与主相机在同一次 supplementary 采集中同时记录。

带 after_cycle 阶段。模型可读取图片和相机视角元数据，私有遮挡标签不进入导出包。

实验脚本保存在 `.runtime/grasp-evaluation/capture_alternate_view.py`，在仓库根目录通过
`python -c "import runpy; runpy.run_path('.runtime/grasp-evaluation/capture_alternate_view.py', run_name='__main__')"`
执行。正常结束后相机位置、工件位置恢复，临时板删除，各 Gazebo 服务均返回成功。
这只是改变观察条件，没有修复感知代码，也不表示模型自主控制了相机。

## 本轮自审与范围结论

本轮的必要缺陷已修复并验证，实际侧视证据改善了定位，但物理机制仍有误判。
本次比赛 Demo 的计划验收以有限案例、可核实证据、软件回证、外部检查建议和补证出口为范围，
接受已公开的误诊及未知。五轮没有证明通用抓取诊断准确率，也没有实现完整夹持/保持物理。
后续提高物体身份判断、区分遮挡与视场覆盖、减少重复取证，应以新的案例和证据评测，
不作为本次已完成 Demo 范围的隐藏能力。
