## 0. 一句话定位

**大模型主导调查，但不主导事实。** 证据是现实世界唯一的入口；"哪里坏了、哪里排除了、哪些还分不开、
下一步该取什么证据"由宿主计算，不是模型说了算。

这句话是初赛"确定性验收：模型不判定自己的成果"的深化——复赛把它推进到"模型不判定事实"。

## 1. 系统边界

固定的视觉引导抓取工位（Gazebo 仿真，UR5e，工件 A/B，任务 PICK-A17）。

| 边界 | 说明 |
|---|---|
| 任务范围 | 止于**机器人到位**。不做接触、夹持、抬起、保持的物理验证 |
| 角色分离 | 仿真、故障注入与评分属于 harness；**产品不读取故障答案**，`scenario-labels` 只用于评测 |
| 输入 | 一次运行的导出包：图像、深度、检测记录、配置、指令、运动、结果、运行版本；可附正常参考运行 |
| 输出 | 判定（可疑/排除/未查）、假设、核算隔离、交接说明或补丁，全部带证据引用与检查范围 |
| 不承诺 | 通用设备接入、多租户、规模化运维、统计准确率 |

三层分工对应两层诊断：**隔离**回答哪个节点坏了（结构分析＋残差，软件层）→ **机理**回答怎么错的
（测量工具，软件层）→ **实现**回答错在哪段代码（源码层）。

## 3. 各部分现状

### 3.1 案件与证据

每条证据带来源、哈希、时钟域、任务阶段和**证据层**（现场观测 / 软件层 / 源码层），层由导出方声明。
案件记录哪些证据真被读取过；同一案件可挂多次观察（故障运行＋正常参考运行＋复核运行）。
派生证据（如核算结果）取来源中最深的一层。案件落盘，重启后仍在。

### 3.2 系统图与领域知识

12 个节点、17 条关系，其中 4 个是**承载软件的节点**（源码层只能在其下展开）。10 类领域知识卡。
图是抓取任务的参考模型，不是自动发现的拓扑，也不是统计学出来的因果网络。

### 3.3 工具面

12 件工具。默认开放 9 件；源码三件由门开放。模型每轮最多 20 次调用。
所有工具只给读数与记录，不给结论；调用参数与返回值都留档，可在工作台逐条展开核对。

### 3.4 诊断模板与结构引擎

模板里存四样东西：**方程、变量、测量、故障挂接**。再附若干**预先实现的检验**
（用到哪几条方程、需要哪些测量、残差计算器、阈值及阈值来源）。

| 模板 | 方程 | 测量 | 故障模式 | 检验 |
|---|---|---|---|---|
| 几何指令链 `geometry_chain` | 11 | 6 | 8 | A 指令一致、B 运动跟踪、C 到位一致 |
| 帧对应 `frame_correspondence` | 1 | 2 | 1 | D 帧对应 |
| RGB-D 交接 `depth_handoff` | 4 | 5 | 4 | F 交接保真、G 感知守约、H 原始可测 |

合计 16 条方程、13 个故障模式（落在 9 个图节点上）、7 项检验。故障只挂到**节点粒度**，
模板里不写"工具补偿被用了两次"这类机理——机理归测量工具和源码层。

**结构引擎是通用的，与具体模板无关**，运行时现算：

1. **关联矩阵 / 二部图**：方程 × 未知变量。测量一旦绑定，对应变量变为已知，不进矩阵。
   所以同一模板在不同案件里结构不同：**证据缺什么，结构就少什么冗余**。
2. **过约束部分**：最大匹配 + Dulmage–Mendelsohn 分解。
3. **可检测**：故障挂接的方程落在过约束部分内。
4. **可隔离**：去掉故障 j 的方程后 i 仍可检测，则 i 与 j 可分；输出隔离矩阵与不可区分组。
5. **可用检验**：所需测量都已绑定，且其方程集在当前结构下确实过约束。
   **检验对哪些故障敏感由结构推出，不手写**——所以特征表不会被质疑为照着注入故障定制。
6. **缺口与区分建议**：缺检验（结构可分但无现成检验）、缺测量（结构上就不可分）、
   以及"绑定哪条记录能把当前候选分开"。

**明确不做**：MSO 自动枚举、残差自动生成、从方程做符号或数值求解。

### 3.5 隔离的四种身份

在三条写进输出的假设下给出：单故障；故障一定会让对它敏感的检验违反；结构只看方程含哪些变量，数值由残差计算器给。

| 身份 | 含义 | 强度 |
|---|---|---|
| **剩余候选** | 所有违反的检验都对它敏感，且未被任何通过的检验排除 | 最强（假设成立时） |
| **核算排除** | 对它敏感的某个检验通过了 | 强，可被新证据反驳 |
| **未检验** | 没被排除，但解释不了全部违反。**不等于正常** | 弱 |
| **不可检测** | 现有测量够不着它，通过的检验对它无话可说 | 无结论 |

### 3.6 两层诊断与门

- **软件层**只看跑起来的程序：运行版本、实际加载的配置、模块输入输出、日志、按记录输入复跑。
  定位在这一层完成，**没有源码也能做到**，出口是改配置或带复现输入交开发方。
- **源码层**要同时满足：软件层已把异常定位到承载软件的节点；绑定源码版本与观察包记录的运行版本一致。
  源码只解释已定位异常的机制并生成补丁；只引用源码的判定会被降为未查。

门链：源码层门 → 补丁门（补丁必须回答一个 `source_patch` 假设，且目标有软件层定位）→
人工审批（认的是冻结过的那一份方案）→ 落地到专用副本 → **现场复核**（新采集的运行，并在其上重算同一组检验）。

两条宿主规则：

- **R1**：判定若引用了核算结果，不能把核算隔离出的唯一候选说成排除，也不能把核算已排除的节点说成可疑。违反即退回重写。
- **R2**：核算排除的节点不计入软件层定位，因此不能打开源码层，也不能提交补丁。

### 3.7 工作台

```text
┌──────────┬───────────────────────────┬──────────────────────┐
│ 案件侧栏  │ 标题                       │ 状态条（吸顶）        │
│          │ ┌─────────────────────┐   │ 接入条 / 源码层状态    │
│          │ │ 对话（自己滚动）      │   │ 抓取系统图（可折叠）   │
│          │ └─────────────────────┘   │ ┌──────┬──────┐      │
│          │ 输入框                     │ │宿主核算│模型主张│     │
└──────────┴───────────────────────────┴──────────────────────┘
```

- **状态条**：阶段（取证 → 调查中 → 已定位 → 待审批 → 待应用 → 待现场复核 → 已复核）·
  当前成立的结论 · 下一步。结论优先取宿主核算；没有核算时显示模型可疑并注明"未经核算"。
- **宿主核算页**：核算隔离（检验表、四种身份、区分建议、关联矩阵与可隔离性矩阵）、现场复核、证据清单、当前连接。
- **模型主张页**：检查依据与未决项、分组概览、当前假设与交接说明、候选补丁与审批。
- **系统图**作两栏共用底图：**边框颜色是模型判定，底色是宿主核算**；两者不一致时明确标出。

界面按来源分栏本身就在讲"模型主导调查、不主导事实"，答辩时切页签即可，不必口头解释。

## 4. 已验证范围

### 4.1 确定性核对（宿主工具直接调用，不经模型）

五个真实导出包上的结果：

| 运行 | A 指令一致 | B 运动跟踪 | C 到位一致 | D 帧对应 | 隔离结果 |
|---|---|---|---|---|---|
| 正常参考 | 通过 | 通过 | 通过 | 通过 | 无违反 |
| 几何软件故障 | **违反 70.0 mm** | 通过 | 通过 | 通过 | 唯一候选：指令计算与接口 |
| 旧帧消费 | 通过 | 通过 | **违反 46.1 / 50.8 mm** | **违反，时差 5.5 / 22.2 s** | 唯一候选：采集与帧对应 |
| 修复后复核 | 通过 | 通过 | 通过 | 通过 | 无违反 |
| 目标深度缺失 | 未核算 | 未核算 | 未核算 | — | 几何链故障不可检测 |

深度缺失另用 RGB-D 交接模板：F 违反（原始 1.00 / 消费 0.14）、G 通过、H 需绑定参考运行；
唯一候选为采集交接的深度交接模式，不绑参考运行时成像与工件表面为**不可检测**。

**几何故障与旧帧消费是同一个现象**（A、B 都没到位，偏 5–7 cm），核算把它们分到不同节点，出口也不同。
这是演示的骨架，全部来自已有真实运行。

### 4.2 真实模型（`mimo-v2.5-pro`，不给故障标签，同一提问）

| 运行 | 耗时 | 结论 | 报告质量 |
|---|---|---|---|
| 几何故障 · 不读源码 | 559 s | 定位正确，引用核算 | 机理归因错误；R1 触发一次并被正确修正 |
| 旧帧消费 · 不读源码 | 410 s | 定位正确 | 工件位移为推断；不可隔离的理由写错 |
| 深度缺失 · 含源码 | 305 s | 定位正确，并按"不可检测"提出补测 | 哈希说错；字段含义读错；补测未执行 |
| 旧帧 · 同输入重复 | 155 s | 与首次一致 | 一次都没进入多候选，区分建议未出现 |
| 几何 · 同输入重复 | 359 s | 与首次一致 | 未做机理测量，收窄后的提示词效果未知 |

**结论：定位与排除这一步是可信的、且由宿主计算；"为什么会这样"仍然出错。**

## 5. 现在不能宣称的事

- 核算**只对模板覆盖的节点负责**。"未检验"和"不可检测"都不等于正常。
- **单故障假设**。复合故障时可能没有剩余候选，系统照实输出"单故障假设不成立，或原因在模板之外"。
- 模板是**人工整理的参考模型**；方程与故障挂接属于领域知识，不是学出来的。
- 阈值多为模板默认并已标注，且是**看过这些数据之后设定的**；检验 C 的余量不到两倍。
- 检验 C 只比较到位误差大小，方向不同而大小相同的偏差会漏检。
- **未演示**：模型按区分建议主动补证；缺测量时主动请求新来源。现有案例信号太清楚，模型用不上提示。
- 模型对**机理**的解释仍然出错，第六轮的同类错误在第七轮复现。
- 实验规模很小，且开发过程中改过提示与工具，**不是对照实验**，不换算成通用准确率。
