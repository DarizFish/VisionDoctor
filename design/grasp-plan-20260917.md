## 1. 方案要成立的那句话

**LLM 主导调查，证据是唯一事实入口，结构分析与残差检验把"哪里坏、哪里排除、哪些还分不开、
下一条该取什么证据"变成宿主事实。**

完整形态下，一次诊断应该是这样闭环的：

```text
现象 → 模型提竞争解释 → 宿主算出"用现有证据能分开什么"
                              │
                   ┌──────────┴──────────┐
              分得开                  分不开
                   │                      │
            跑检验 → 隔离            宿主给出"缺哪条测量"
                   │                      │
            机理 → 处理出口      模型去取那条证据 → 回到上一步
```

**左半边已经实现并实测；右半边（缺测量 → 模型主动补证 → 再核算）只在确定性核对里验证过，
真实模型从未走过一次**——因为现有案例信号太清楚，模型不需要提示就能定位。这是方案与 Demo 之间
最主要的一条缺口，下面 P2 就是为补这条缺口设计的。

## 2. 方案与当前 Demo 的差距

| 方向 | 当前已实现 | 当前实测范围 | 方案中的更广形态 |
|---|---|---|---|
| 系统图与知识 | 12 节点、17 关系、10 类知识 | 真实模型已查询并绑定结论 | 覆盖更多工件与故障机制 |
| 诊断模板 | 3 个模板、16 条方程、13 个故障模式、7 项检验 | 五个真实导出包上复现预期隔离 | 更多模板；模板之间共享变量形成更大结构 |
| 结构分析 | 通用引擎：关联矩阵、DM 分解、可检测/可隔离、可用检验、缺口与区分建议 | 与已知故障类别一致（阈值在看过数据后设定） | 对"不可检测"也给出补测建议；单模板结论标注"模板内" |
| 取证闭环 | 区分建议已计算并显示 | **未演示**模型按建议取证 | 模型按缺测量主动请求新来源，形成多轮收敛 |
| 两层诊断 | 软件层/源码层、四道门、R1/R2 | 无源码时定位并交接；有源码时补丁落地并 Gazebo 复核 | 源码层入口再加一条：绑定源码里确实包含被定位模块 |
| 机理解释 | 变换链核算等测量工具 | **仍然出错**（归因、哈希、字段含义） | 机理也要有可核对的计算依据，而不只是模型叙述 |
| 故障假设 | 单故障，写进输出 | 复合故障未测 | 复合故障如实输出"假设不成立"，不强行给候选 |
| 任务闭环 | 到位反馈 | 到位误差与未生成命令 | 夹持、抬起、滑移与保持的真实验证（**超出本次比赛范围**） |

## 3. 路线

### P0 / P1（已完成，列在这里是为了让本文可独立阅读）

通用结构引擎、三个模板与七项检验、`structural_diagnose` 工具、隔离结果进入案件与模型视图、
R1/R2 两条宿主规则、工作台核算面板与系统图标记、现场复核时重算同一组检验。
实测见 [第七轮记录](results/grasp-round7-20260916.md)。

### P2：让"缺测量 → 补证"真的发生（**下一步，未开始**）

| 工作 | 状态 | 对 Demo 的价值 | 怎么验证 |
|---|---|---|---|
| **相机外参物理漂移场景** | 未开始 | 这是唯一天然留下多个候选的案例：检验 A、B 通过、C 违反，标定与工具在结构上不可区分 → 宿主给出"缺测量" → 模型必须去补证。正好回应初赛提出的"是软件还是标定"痛点 | 新建仿真场景（改相机位姿、不改配置），Gazebo A/B 实跑，再跑一次真实模型诊断，记录模型是否按建议取证 |
| **不可检测也给补测建议** | 未开始 | 现在只有候选≥2 时才给建议；深度案例里"成像不可检测"没有配套的"绑定参考运行即可检测" | 确定性核对复现；深度案例上应出现"绑定参考深度 → H 可用" |
| **单模板结论标注"模板内"** | 未开始 | 只核算一个模板时的"唯一候选"容易被读成全局结论，这是现在最容易被评委问住的地方 | 工作台显示；旧帧案件只绑几何链时应显示"模板内唯一候选" |

P2 做完，演示才能讲完整的闭环：**同症状 → 分不开 → 系统说缺什么 → 取到 → 分开了。**

### P3：完备性（有价值，排在 P2 之后）

| 工作 | 状态 | 说明 |
|---|---|---|
| 源码层入口再加一条检查 | 未开始 | 绑定的源码里确实包含被定位的模块，避免"版本对上但模块不对" |
| 诱导对照 | 未开始 | 源码里放一段有误导性的注释，检验模型会不会被注释带走；这是"只引用源码的结论会被降为未查"这条规则的反面验证 |
| 机理的可核对依据 | 未开始 | 现在"哪里坏"有计算，"怎么错"只有叙述。至少应做到：机理结论必须引用某个测量工具的具体输出字段与数值 |
| 更多模板 | 未开始 | 按"有真实故障数据、能真实计算"来选，不为凑数而加 |

### 明确不做

| 不做 | 理由 |
|---|---|
| MSO 自动枚举、残差自动生成、方程求解 | 检验提前写好即可；结构分析只负责判断它们是否成立、对谁敏感 |
| 独立的手眼标定 / 相机几何检查工具 | 工位没有独立测量来源，做出来只能是假的。由结构分析如实给出"缺测量"更诚实 |
| 把结构分析、残差、隔离拆成多个工具 | 工具越多模型越容易漏用；第六轮有工具一次都没被调用过 |
| 模板描述语言、项目自动映射到模板 | 属于企业化工程；让 LLM 绑定证据已足够展示"开放世界映射 + 确定性计算" |
| 多故障诊断、概率排序 | 显式声明单故障假设即可；概率需要统计依据，现在没有 |
| 接触、夹持与保持的物理闭环 | 用户已明确当前建设止于机器人到位 |
| 多租户、企业权限、规模化调度 | 不属于本次比赛重点 |

## 4. 演示怎么讲（方案形态）

1. **同一症状**：两次运行 A、B 都没到位，偏 5–7 cm。先看结构分析：只凭抓取记录，指令计算和机器人能单独分出，
   感知、帧对应、标定、工件、偏移、工具六者分不开。
2. **几何软件故障**：A 违反 70 mm、B/C 通过 → 唯一候选"指令计算与接口"。不给源码时交开发方；
   给源码时开放源码层 → 补丁 → 审批 → 落地 → 现场复核，复核时检验 A 从 70 mm 回到 0，其余保持通过。
3. **旧帧消费**：A、B 通过、C 违反 → 剩余六个候选 → 区分建议"绑定采集记录" → 检验 D 违反 →
   唯一候选"采集与帧对应"。**（当前由确定性核对与工作台展示；真实模型尚未走过这条路径。）**
4. **深度缺失**：原始可测、交接丢失、感知按规则拒绝；拿掉参考运行，成像故障变为"不可检测"——
   系统会老实说"这个我现在判断不了"。
5. **（P2 之后）相机漂移**：分不开 → 缺测量 → 现场补一次独立测量 → 分开。
6. **边界**：模板覆盖不到的案例（如遮挡）仍由模型读图取证，那部分没有宿主核算兜底。

答辩时切"宿主核算 / 模型主张"两个页签，布局本身就在讲这套分工。

## 5. 不变量（任何一步都不能破的约定）

- **真实模型与 Gazebo 必须实际运行才算验证**；只写不跑不算完成。
- **不推送**，除非明确要求。
- 仿真、故障注入与评分归 harness，**产品不得读取故障答案**。
- **方案、已实现能力、实际验证范围分别说明**；允许方案领先 Demo，不得把规划写成已验证结果。
- 不偏离初赛提交：本方向是**深化**（模型不判定自己的成果 → 模型不判定事实），不是推翻。
- 演示材料里不放密钥。

## 6. 风险与应对

| 风险 | 应对 |
|---|---|
| 模板被质疑为照着注入故障定制 | 故障只挂到节点、不含机理；检验敏感性由结构推出而非手写；正常与修复后运行全部通过；旧帧与几何隔离到不同节点。仍要写明它是人工参考模型 |
| 阈值影响判定 | 输出必须带阈值来源；项目未声明的用模板默认并标注；如实写明阈值是看过数据后设定的 |
| 单故障假设不成立 | 照实输出"没有候选能解释全部违反"，不强行给结论 |
| 模型不用新工具 | 靠模型视图里的模板目录与区分建议引导，结果按实测报告，不强制 |
| 模型机理解释出错 | 当前如实记录在实验报告里；P3 的"机理必须引用具体输出字段"是正面应对 |
| 到位误差依赖独立测量 | 仿真里来自工位真值；真实现场对应外部测量或人工报告，演示时讲清楚 |
