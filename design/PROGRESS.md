## 2026-09-16：结构诊断

**已实施并实测。** LLM 主导调查；在模板覆盖的节点上，"哪里坏、哪里排除、哪些分不开"由宿主计算，模板外仍靠模型取证。详见 [第七轮记录](results/grasp-round7-20260916.md)。

- **模板**：几何指令链、帧对应、RGB-D 交接三个，保存方程、变量、测量、故障挂接与预实现检验，故障落在系统图节点上。
- **结构引擎**：通用。关联矩阵 → 过约束部分 → 可检测 / 可隔离 → 可用检验 → 缺检验 / 缺测量 → 区分建议。不做 MSO 自动枚举。
- **宿主规则**：引用核算不能说反话；核算排除的节点不能打开源码层。
- **工作台**：核算隔离面板、系统图底色标记、分歧标注；现场复核时重算同一组检验。
  右栏按来源分成"宿主核算"与"模型主张"两个页签，系统图作为共用底图放在两者之上，顶部一条常驻状态条给出当前阶段与下一步。

|---|---|---|

- **宿主规则**：可疑和排除必须引用非源码证据；同一轮同一对象只能有一条判定。
- **系统图**：去掉"运行代码与配方"节点，现为 12 个节点、17 条连线。证据层由观察包导出方声明。

- 基准包含会话、附件处理、项目理解、隔离 Git worktree、Docker 运行器、补丁策略和产品内 Gazebo
  路径。

- `harness/gazebo/` 拥有独立的 PICK-A17 SDF 场景、ROS 相机/运动探针、Git bundle 生成器、本地
  控制器与 Streamlit 操作台；它复用已验证的 `visiondoctor/ros-gazebo:jazzy-v1` 运行镜像，但保留
  自有容器、挂载、运行目录与导出边界。Python 源码没有产品 import 或产品 API 路由。
- 独立项目的故障 HEAD 将逆 TCP/工具补偿重复两次；正常提交只应用一次正确的逆工具变换。故障 TCP 因而
  稳定停在工件上方约 70 mm，而不是压入低矮工装。判定采用到位误差，不实现物理附着/搬运。
- 工位使用大台面，UR5e 固定在台面上；A/B 工件均位于基座前方同一已实测可达区域的低矮定位座中。RGB-D

  向实时 IK 提供固定初始关节状态，执行目标仍完全来自项目工作区的算法输出，完成以实测关节到位为准。
- 每次节拍的 manifest 仅清点相机、视频、算法 I/O、日志、配置、提交和轨迹等公开证据；私有评分资料
  位于未导出的 harness 路径。每个 artifact 记录采集时刻和时钟域，导出前会核验其 SHA-256；脱敏、
  时钟元数据与导出边界已有确定性测试。
- 基准原有 RGB-D 场景和外参求逆 bundle 仍是历史基准，不是此 M1 的实现依赖。

## 当前最高风险

1. 若先迁移 UI 或旧 Gazebo API，会扩大改动面，却不能证明多模态证据定界有效。
2. 若环境适配器能触发运动或写配置，“只读采集”边界会失效。
3. 若不记录时钟质量，视频、算法输出和机器人轨迹的关联会产生伪归因。
4. **风险：** A/B 的实测结果与当前 UR5e、MoveIt 参数、大台面、定位台、工具配置和目标姿态绑定；
   若改变这些资产，必须重新验证故障与正常两侧的完整往返，不能沿用当前结论。
