## 冻结的意义

`frozen_hash` 是补丁内容 + 目标段 + 基线提交的哈希。批准记录的是"某人批准了这个哈希"。
之后补丁再改一个字符，哈希就变，审批门立刻返回 `the plan changed after it was reviewed`，
批准作废。批准之前，门返回 `no one has decided on this plan`。

## 落地方式

批准之后，宿主把冻结的那份 diff `git apply --index` 到绑定的仓库并提交——
让人手抄 diff 是这条路上唯一能混进未审内容的地方，所以由宿主写。
`--index` 保证提交里只有被审过的路径。

提交消息带上审批人、冻结哈希和基线提交，事后追溯不依赖产品的内存状态。

## 边界

产品写到仓库为止。**合入主线、部署到工位是人的动作**，产品只记录"已应用"的时刻——
这个时刻是现场复核的分界线。
